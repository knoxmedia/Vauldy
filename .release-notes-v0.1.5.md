## What's New (2026-08-07 ~ 2026-08-19)

### Platform Requirements

**Linux binary (`vauldy-linux-*`)**

- Requires **glibc (LIBC) ≥ 2.18**
- Distros below this baseline (e.g. CentOS 7 / RHEL 7 with glibc 2.17) are not supported for the standalone Linux binary
- Prefer the **Docker image** (`knoxmedia/vauldy`) on older or minimal hosts — the container bundles compatible runtime dependencies

Windows and macOS binaries are unchanged; no additional libc requirement.

### Docker & Deployment
- Multi-arch images published to **Docker Hub** as `knoxmedia/vauldy` (`linux/amd64` + `linux/arm64`)
- GitHub Actions workflow builds and pushes tagged images on release
- Container-friendly default config shipped at `docker/config.yml` (ffmpeg paths, data directories)
- `docker-compose.yml` and README updated to pull the published image
- **amd64 images**: bundle HW-accelerated ffmpeg from the release tar.gz (NVENC/NPP/fdk-aac); pass `--gpus all` with NVIDIA Container Toolkit for GPU transcode
- **arm64 images**: use Debian ffmpeg (software transcode only)

### Publication & Startup Reliability
- Startup auto-repairs missing policy-v3 plan dependency edges from `config_snapshot_json` when steps still match the snapshot
- Recovers from cross-edition / schema-rebuild scenarios that empty `media_ingest_step_dependency` while leaving ingest runs intact (e.g. switching between community and commercial builds on the same data directory)
- True graph drift (wrong requiredness, wrong edge targets) is still rejected — only missing edges are restored

### Task Execution & SQL
- Post-ingest lease renewal tolerates transient `SQLITE_BUSY` during long-running tasks (preview, etc.); retries within the heartbeat budget instead of failing the task
- Task overview uses top-N list queries instead of paging, reducing N+1 reads
- SQL compatibility fixes ported from commercial multi-DB work: `GROUP BY` json expressions, `EXISTS` → `CASE WHEN` for SQLite, transcode adapter join rewrite

### Community Edition
- DRM routes and tables gated out of the community build via `coreiface` module isolation
- Community binaries remain `vauldy-*`; no commercial-only symbols in the open build

## 中文摘要

- **Linux 要求**：独立 Linux 二进制需要 **glibc (LIBC) ≥ 2.18**；CentOS 7 / RHEL 7（glibc 2.17）等旧系统请改用 Docker 镜像 `knoxmedia/vauldy`
- **Docker 部署**：Docker Hub 发布 amd64/arm64 多架构镜像；amd64 内置硬件加速 ffmpeg（需 NVIDIA Container Toolkit + `--gpus all`），arm64 使用软件转码
- **发布管线可靠性**：启动时从 snapshot 自动补回缺失的 v3 依赖边，避免跨版本共用数据目录后 `persisted policy v3 graph differs from snapshot` 导致无法启动
- **任务与 SQL**：长任务租约续期容忍 SQLite 忙锁；任务概览查询优化；SQLite 兼容 SQL 修正
- **社区版**：DRM 模块与社区构建隔离，开源版不含商业 DRM 路由与表
