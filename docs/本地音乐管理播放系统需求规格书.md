## 1. 项目概述

### 1.1 背景

随着个人数字音乐收藏的积累，本地磁盘上散落着来自不同来源的音频文件（MP3、FLAC、AAC 等）。这些文件往往缺乏统一的组织结构，元数据（标签）不完整，难以系统性地浏览、检索与播放。

本系统旨在构建一个面向个人用户的**本地音乐归纳收录与播放一体化平台**，参考 Plex Media Server 的音乐管理模式，实现本地磁盘目录扫描 → 自动归类入库 → 专辑/艺人/标签管理 → 流畅播放体验的完整闭环。

### 1.2 目标

- 自动扫描指定磁盘目录，识别并入库所有音频文件
- 以专辑、艺人、流派等维度对音乐进行结构化组织
- 支持收藏夹、播放列表等个性化管理功能
- 提供功能完整的本地音乐播放器（含均衡器、队列管理等）
- 支持元数据的浏览、展示与手动编辑
- 无需联网即可完整运行（离线优先）

### 1.3 范围边界

| 范围内 | 范围外 |
|--------|--------|
| 本地磁盘音频文件管理 | 在线流媒体播放（Spotify / Apple Music 等） |
| 元数据读取与编辑 | 音乐下载功能 |
| 本地播放器 | 多用户/多账号系统 |
| 播放列表管理 | 社交分享功能 |
| 局域网内设备播放（可选） | 版权保护内容解密 |

## 2. 术语定义

| 术语 | 定义 |
|------|------|
| **媒体库（资料库）** | 用户指定的一组磁盘目录，系统在其中扫描并管理音频文件的集合 |
| **音轨（Track）** | 单个音频文件，对应一首歌曲 |
| **专辑（Album）** | 按专辑名称聚合的一组音轨 |
| **艺人（Artist）** | 音轨/专辑的演唱者或创作者 |
| **流派（Genre）** | 音乐风格分类标签，如流行、摇滚、古典等 |
| **元数据（Metadata）** | 嵌入音频文件或由系统维护的描述信息，包括 ID3 标签等 |
| **播放列表（Playlist）** | 用户手动创建的有序音轨集合 |
| **收藏（Favorite）** | 用户对音轨/专辑/艺人的快速标记，用于快速访问 |
| **扫描（Scan）** | 系统遍历指定目录、识别音频文件并更新数据库的过程 |
| **队列（Queue）** | 当前播放顺序的临时列表 |

## 3. 用户画像与使用场景

### 3.1 目标用户

- 个人音乐收藏爱好者，拥有数百至数万首本地音乐文件
- 习惯使用 NAS 或个人电脑存储音乐的用户
- 对音质有一定要求，收藏有 FLAC 等无损格式文件
- 希望摆脱在线流媒体平台、保持完整离线体验

### 3.2 典型使用场景

**场景 A — 初次入库**  
用户首次打开应用，添加 D:\Music、E:\FLAC 等多个目录作为媒体库，系统自动扫描并将所有音频文件分类归档为专辑和艺人列表。

**场景 B — 日常浏览**  
用户打开资料库，按专辑视图浏览，找到某张专辑后查看音轨列表，点击播放。

**场景 C — 整理收藏**  
用户发现部分文件的专辑/艺人信息标注为"Unknown"，通过元数据编辑器手动修正，并为专辑评分、收藏。

**场景 D — 创建播放列表**  
用户将不同专辑的歌曲拖拽组合成"下午工作"播放列表，并设置随机播放模式。

**场景 E — 新文件入库**  
用户下载了新专辑并放入已监控目录，系统自动检测到文件变化并将新文件追加入库，无需手动重新扫描全库。

## 5. 功能需求

### 5.1 本地磁盘扫描与入库

#### 5.1.1 媒体库目录配置

| 需求ID | 描述 | 优先级 |
|--------|------|--------|
| SCN-001 | 用户可添加一个或多个本地目录作为媒体库路径 | P0 |
| SCN-002 | 支持排除特定子目录（如 Temp、Download 临时目录） | P1 |
| SCN-003 | 媒体库配置持久化保存，重启后自动加载 | P0 |
| SCN-004 | 支持为不同媒体库设置别名（如"古典音乐"、"流行收藏"） | P2 |

#### 5.1.2 扫描行为

| 需求ID | 描述 | 优先级 |
|--------|------|--------|
| SCN-010 | 支持全量扫描：遍历所有配置目录下的音频文件 | P0 |
| SCN-011 | 支持增量扫描：仅处理自上次扫描后新增/修改的文件 | P1 |
| SCN-012 | 支持文件系统监听（FSWatch），当目录内有文件变化时自动触发增量扫描 | P1 |
| SCN-013 | 支持的音频格式：MP3、FLAC、AAC（m4a）、OGG、WAV、AIFF、APE、WMA | P0 |
| SCN-014 | 扫描时显示进度（已扫描文件数 / 总文件数、当前处理路径） | P1 |
| SCN-015 | 扫描结束后输出入库报告（新增数量、更新数量、失败文件列表） | P1 |
| SCN-016 | 扫描失败文件（无法解析、格式不支持等）单独记录，不阻断整体扫描流程 | P0 |

#### 5.1.3 元数据提取规则

系统从以下来源按优先级提取元数据：

1. **音频文件内嵌标签**（ID3v2 / Vorbis Comment / APEv2 等）— 最高优先级
2. **文件名模式解析**（`艺人名 - 曲目名.mp3` 等常见命名规则）— 回退方案
3. **目录结构推断**（`/艺人名/专辑名/曲目名.mp3` 目录层级）— 最低优先级

| 字段 | 说明 |
|------|------|
| 曲名（Title） | 必填，缺失时使用文件名（去扩展名） |
| 艺人（Artist） | 支持多艺人（分隔符：`;` 或 `/`） |
| 专辑艺人（Album Artist） | 用于合辑归类 |
| 专辑名（Album） | 缺失时归入 `[Unknown Album]` |
| 音轨编号（Track No.） | 用于专辑内排序 |
| 年份（Year） | 可选 |
| 流派（Genre） | 可选，支持多值 |
| 封面图（Artwork） | 内嵌封面 > 同目录 cover.jpg/folder.jpg > 无封面（显示占位图） |
| 时长（Duration） | 从音频流解析，非标签 |
| 比特率（Bitrate） | 从音频流解析 |
| 采样率（Sample Rate） | 从音频流解析 |

## 6. 非功能需求

### 6.1 性能

| 指标 | 要求 |
|------|------|
| 首次扫描速度 | ≥ 200 文件/秒（SSD 环境） |
| 增量扫描响应 | 文件变更后 ≤ 5 秒触发入库 |
| 资料库加载 | 打开资料库首屏渲染 ≤ 1 秒（10,000 首以内） |
| 音频启动延迟 | 点击播放到声音输出 ≤ 500ms |
| 搜索响应 | 输入后 200ms 内展示结果 |

### 6.2 稳定性与容错

- 扫描过程中单个文件解析失败不影响整体流程
- 播放失败时自动跳过并播放下一首，记录失败信息
- 数据库写入采用事务机制，防止异常关闭导致数据损坏
- 应用崩溃后重启，恢复上次播放状态（曲目 + 进度）

### 6.3 兼容性

| 平台 | 要求 |
|------|------|
| 操作系统 | Windows 10+ / macOS 12+ / Linux（Ubuntu 20.04+） |
| 音频格式 | MP3 / FLAC / AAC / OGG / WAV / AIFF / APE / WMA |
| 文件系统 | NTFS / exFAT / APFS / ext4 |

### 6.4 存储

- 数据库文件（SQLite）存储在用户数据目录，与应用本体分离，便于备份
- 封面图缓存存储在应用缓存目录，可清除后重建
- 应用本身不复制、不移动原始音频文件，仅读取

### 6.5 隐私与安全

- 所有数据完全本地存储，不向任何服务器上报用户曲库信息
- 不需要账号注册
- 元数据写回操作前必须获得用户确认

## 7. 数据模型

### 7.1 核心实体关系

```
Library（媒体库）
  └── has many → Track（音轨）

Artist（艺人）
  └── has many → Album（专辑）
  └── has many → Track（通过 TrackArtist 关联）

Album（专辑）
  ├── belongs to → Artist（专辑艺人）
  └── has many → Track（按 track_number 排序）

Track（音轨）
  ├── belongs to → Album
  ├── belongs to → Artist（主艺人）
  ├── has many → Genre（通过 TrackGenre 关联）
  └── has many → Tag（自定义标签）

Playlist（播放列表）
  └── has many → Track（通过 PlaylistTrack 有序关联）

Favorite（收藏）
  └── polymorphic → Track / Album / Artist / Playlist
```

**tracks 表**

| sample_rate | INTEGER | 采样率（Hz） |
| format | TEXT | 文件格式 |
| file_size | INTEGER | 文件大小（字节） |
| file_mtime | INTEGER | 文件修改时间（Unix时间戳） |

| rating | INTEGER | 评分（0-5） |

### 8.3 专辑视图规格

**网格视图**
- 封面图卡片尺寸：160×160px（可调）

- 行高：48px
- 悬浮时行背景高亮

### 8.4 播放栏规格

- 固定在窗口底部，高度：72px
- 左区（30%）：封面缩略图（44×44）+ 曲名 + 艺人 - 专辑
- 中区（40%）：播放控制按钮 + 进度条 + 时间显示
- 右区（30%）：播放模式 + 队列 + 音量控制

## 9. 技术选型建议

### 9.1 桌面应用方案（推荐）

| 层级 | 选型 | 理由 |
|------|------|------|
| UI 框架 | Electron + React / Vue | 跨平台，生态成熟 |
| 音频解码 | Web Audio API + FFmpeg（wasm） | 支持所有主流格式 |
| 数据库 | SQLite（better-sqlite3） | 轻量、零配置、本地文件 |
| 文件扫描 | Node.js fs / chokidar（监听） | 跨平台文件系统访问 |
| 元数据解析 | music-metadata（npm）| 全面支持各格式标签 |
| 搜索索引 | minisearch / flexsearch | 轻量全文搜索 |

### 9.2 备选方案（本地服务模式）

| 层级 | 选型 |
|------|------|
| 后端 | Go / Python (FastAPI) |
| 前端 | Web SPA（React / Vue） |
| 音频转码 | FFmpeg |
| 数据库 | SQLite |
